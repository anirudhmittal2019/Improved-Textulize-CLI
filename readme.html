                                 Selecting lines and rows (--lines)             

Use --lines to show only some of the lines of a file, or some of the rows of a C

    rich test_data/mlb_players.csv --lines 50:70                                
    rich test_data/sections.txt --lines 12:18 -n                                

--line works too, as another name for --lines.                                  

                                      How to write a selection                  

| You write | You get | | --- | --- | | 50:70 | lines 50 to 70 (both included) |
as 50:70 | | 50: | line 50 to the end | | :20 | the first 20 lines | | 7 | just 
1:5,50:70,100: | several sections at once, separated by commas |                

Line numbers start at 1. You can also repeat the option instead of using commas:

    rich test_data/mlb_players.csv --lines 1:5 --lines 50:70 --lines 100        

▌ PowerShell: put comma-separated sections in quotes, e.g. --lines "1:5,50:70". 
▌ PowerShell treats the comma as a list separator. Repeating --lines also works.

                                       How lines are counted                    

 • CSV files: --lines counts rows after the header, so --lines 1:5 shows the fir
   The header is always shown.                                                  
 • Text and code files: --lines counts the lines of the file. Add -n to show the
   numbers.                                                                     
 • Markdown and reStructuredText: the selected lines are rendered (formatted), e
   --lines 1:20.

                            Selecting sections of a document (--section)        

Use --section to show only the part of a document under a heading.              

    rich test_data/sections.txt --section "Instructions"                        
    rich README.md --section "Pager"                                            

Repeat the option to show several sections. They appear in the order they're in 

    rich test_data/sections.txt --section "Overview" --section "Troubleshooting"

                                      What counts as a section                  

A section starts at a heading and continues until the next heading of the same o
Sub-sections are included. Two styles of heading are recognised:                

    ## Instructions              <- Markdown heading (level = number of #)      
                                                                                
    Instructions                 <- Underlined heading, as in reStructuredText  
    ============                    and Markdown (levels go by the order the    
                                    underline styles first appear in the file)  

For example, in test_data/sections.txt (test_data/sections.txt):                

    Project Setup Guide          <- level 1                                     
    ===================                                                         
    Overview                     <- level 2                                     
    --------                                                                    
    Instructions                 <- level 2   --section "Instructions" shows fro
    ------------                                                                
    Windows notes                <- level 3   (a sub-section, so it's included) 
    ~~~~~~~~~~~~~                                                               
    Troubleshooting              <- level 2   ...up to here                     
    ---------------                                                             

Good to know:                                                                   

 • # lines inside fenced code blocks (```) are not treated as headings.         
 • If a title appears more than once, every matching section is shown.          
 • With text and code files, add -n to show the original line numbers. Markdown 
   rendered (formatted).

                                       Table and column names                   

 • The table is called data. You can also use the file name: mlb_players.csv can
   mlb_players. Any - or spaces in the file name become _.                      
 • Column names come from the CSV header. Put names containing spaces or symbols
   SELECT [Height(inches)] FROM data. Do the same for names that are SQL keyword
   or [Group].                                                                  
 • If the header has duplicate names, later ones get a suffix: Name, Name_2.    
 • If a file has no header, the columns are called column1, column2, and so on. 

                                        Upper and lower case                    

 • Text values ignore case, including accented letters. Team = 'bal' matches BAL
   matches JOSÉ. This applies to =, !=, IN, LIKE, ORDER BY, GROUP BY and DISTINC
 • Keywords, column names and the table name can be written in any case: select 
   works.                                                                       
 • To match exact case, add COLLATE BINARY or use GLOB:                         

    rich test_data/mlb_players.csv --sql "SELECT Name FROM data WHERE Team = 'BA
    BINARY"                                                                     
    rich test_data/mlb_players.csv --sql "SELECT Name FROM data WHERE Name GLOB 

Accents are not ignored: jose and josé are different.                           

                                 Combining conditions: AND, OR, NOT             

Use AND, OR and NOT (in any case). AND is applied before OR, so use parentheses 

    rich test_data/mlb_players.csv --sql "SELECT Name, Team, Age FROM data WHERE
    OR Team = 'PHI') AND Age > 40"                                              

| You write | SQL reads it as | | --- | --- | | Team = 'NYM' OR Team = 'PHI' AND
'NYM' OR (Team = 'PHI' AND Age > 40): every NYM player, plus PHI players over 40
OR Team = 'PHI') AND Age > 40 | NYM or PHI players who are over 40 |            

Rich warns you if you mix AND and OR without parentheses. Don't use && or ||:   

 • && is not valid SQL. Rich tells you to use AND.                              
 • || joins text together in SQL (Name || ' (' || Team || ')'), it does not mean
   in a WHERE clause, Rich warns you to use OR.                                 

                                   Text, numbers and empty values               

 • Text values go in single quotes: Team = 'BAL'. Double quotes are for column n
   if you put text in them.                                                     
 • Numbers: columns where every value is a number are treated as numbers, so Age
   numerically, not alphabetically.                                             
 • Leading zeros: values such as zip codes (02134) or IDs (007) are kept as text
   zero isn't lost.                                                             
 • Empty values are NULL. Find them with IS NULL. They are skipped by COUNT(colu
 • Placeholders N/A, NA, null, none, nan and - count as empty in columns that ot
   numbers, so they don't stop the column being numeric. They appear blank in th

                                               Safety                           

Only SELECT queries are allowed (including WITH ... SELECT). Statements that cha
files, such as DROP, DELETE, INSERT, UPDATE, ATTACH and PRAGMA, are blocked, as 
one statement at once.                                                          

                                   Writing queries in PowerShell                

 • Put the whole query in double quotes and text values in single quotes: --sql 
   WHERE Team = 'BAL'".                                                         
 • Use square brackets for column names with symbols rather than double quotes. 
   PowerShell drop double quotes inside an argument.

 • CSV header detection is automatic and sometimes wrong. For example, test_data
